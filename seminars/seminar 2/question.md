# Практическая работа

**Выход:** `.sh` или `.ipynb`. Задачи решаются в консоли или Jupyter.

Задачи разбиты на три уровня. Базовые задачи — обязательный минимум, по ним
отмечают, кто их решил. Список задач с запасом — преподаватель выбирает, что
давать.

## База

### B1. Файлы и каталоги

**need:** нет.

Создайте каталоги `input`, `work`, `result`. В `input` должны находиться два
пустых файла и файл с именем текущего пользователя. Перенесите копии в `work`,
затем удалите там один из пустых файлов.

**Пример:** после решения `ls work | wc -l` → `2` (остались файл пользователя и
один пустой).

### B2. Имена переменных

**need:** нет.

Создайте `student_full_name`, `student_group_name`, `PROJECT_DATA_DIRECTORY`.
Одно значение должно содержать пробелы. Получите имя отчёта из значения группы и
суффикса `_report.txt`.

**Пример:** при `student_group_name='ML 01'` команда
`echo "${student_group_name}_report.txt"` печатает `ML 01_report.txt`.

### B3. Переменные окружения

**need:** нет.

Создайте переменную `COURSE_NAME`. Покажите её видимость в текущей и дочерней
оболочке. Сделайте переменную доступной дочерней оболочке и повторите проверку.

**Пример:** до `export` команда `bash -c 'echo "${COURSE_NAME:-missing}"'`
печатает `missing`; после `export COURSE_NAME` — значение переменной.

### B4. Сборка файла

**need:** три текстовых файла в каталоге `parts` (`01.txt`, `02.txt`, `03.txt`).

Соберите `document.txt` из трёх частей. Создайте `document-draft.txt` с
дополнительной строкой `DRAFT`. Исходный документ не должен измениться.

**Пример:** если каждая часть — одна строка, то `wc -l < document.txt` → `3`,
а `wc -l < document-draft.txt` → `4`.

### B5. Удаление

**need:** файл, пустой каталог и непустой каталог.

Удалите файл и пустой каталог. Попытайтесь удалить непустой каталог как пустой
(`rmdir`) и сохраните сообщение об ошибке.

**Пример:** `rmdir non-empty-directory` завершается ошибкой вида
`rmdir: failed to remove 'non-empty-directory': Directory not empty`.

### B6. Права

**need:** файл `run.sh` и каталог `shared`.

Установите для `run.sh` права `rwxr--r--`, для `shared` — `rwxr-x---`. Покажите
права в символьном и числовом виде.

**Пример:** `stat -c '%a %n' run.sh shared` → `744 run.sh` и `750 shared`.

## Среднее

### M1. Стандартные потоки

**need:** существующий и несуществующий путь.

Получите обычный вывод и ошибку одной команды. Сохраните их раздельно, затем
вместе в одном файле. Добавьте в общий файл ещё одну строку, не потеряв
предыдущий результат.

**Пример:** для `ls exists.txt missing.txt` файл `stdout.txt` содержит
`exists.txt`, а `stderr.txt` — строку об отсутствии `missing.txt`.

### M2. Пайплайн

**need:** Linux, `/etc/os-release`.

Постройте пайплайн, который сохраняет содержимое `/etc/os-release`, оставляет
первые пять строк и считает их. Повторите пайплайн с несуществующим файлом.
Сохраните коды завершения в обычном режиме и в режиме `pipefail`.

**Пример:** рабочий пайплайн печатает `5`; с несуществующим файлом при
`set -o pipefail` код завершения ≠ `0`.

### M3. Фоновый процесс

**need:** нет.

Запустите процесс в фоне. Покажите его PID, родительский PID, состояние и
команду. Завершите процесс корректно и подтвердите завершение.

**Пример:** после `kill -TERM` и `wait` команда `ps -p "$pid"` не находит
процесс (печатается `finished`).

### M4. Сигналы

**need:** нет.

Запустите процесс в фоне. Приостановите процесс, продолжите работу и корректно
завершите. Зафиксируйте состояние после каждого действия.

**Пример:** после `kill -STOP` поле `STAT` в `ps` содержит `T`; после
`kill -CONT` — снова `S`.

### M5. Копия каталога

**need:** каталог `source` с десятью файлами разного размера.

Создайте копию `source` в `destination`. Подтвердите совпадение количества
файлов и размера каждой пары.

**Пример:** `ls source | wc -l` и `ls destination | wc -l` дают одинаковое
`10`.

### M6. Информация о системе

**need:** Linux.

Создайте `system.txt` с информацией о kernel, операционной системе,
пользователе, домашнем и текущем каталогах. Покажите доступность средств
наблюдения за CPU, памятью и GPU.

**Пример:** `grep -c . system.txt` ≥ `5`; при отсутствии инструмента печатается
строка вида `nvidia-smi: not found`.

## Сложное

### H1. Диагностика системы

**need:** Linux.

Создайте каталог отчёта. Раздельно сохраните информацию о системе, процессах,
диске, памяти, доступных средствах наблюдения и возникших ошибках.

**Пример:** в каталоге `report/` появляются `system.txt`, `processes.txt`,
`tools.txt`, `errors.txt`; при отсутствии ошибок `errors.txt` пуст.

### H2. Менеджер процессов

**need:** нет.

Создайте worker, принимающий время работы и код завершения. Запустите три
worker-процесса в фоне с отдельными логами. Дождитесь всех процессов. Итоговый
код должен отражать ошибку любого worker.

**Пример:** worker'ы с кодами `0`, `1`, `0` → итоговый код скрипта `1`; каждый
лог (`worker-1.log`…`worker-3.log`) существует.

### H3. Резервная копия

**need:** каталог `project` с файлами и пустой каталог `backups`.

Создайте резервную копию через временный каталог. Подтвердите количество и
размеры файлов. Готовая копия `backup-ready` должна появиться только после
успешной проверки.

**Пример:** при успехе существует `backups/backup-ready`, а промежуточный
`backups/staging` отсутствует.

### H4. Надёжный пайплайн с обработкой ошибок

**need:** нет.

Напишите скрипт `pipeline.sh FILE`, который печатает число непустых строк файла
и завершается кодом `0`; при отсутствии файла печатает сообщение в stderr и
завершается кодом `1`. Используйте `set -euo pipefail`.

**Пример:** `./pipeline.sh /etc/os-release` → печатает число и код возврата
`0`; `./pipeline.sh /missing` → сообщение в stderr и код возврата `1`.

### H5. Ротация логов по размеру

**need:** файл `app.log`.

Напишите `rotate.sh LOGFILE MAXBYTES`: если размер `LOGFILE` больше `MAXBYTES`,
переименуйте его в `LOGFILE.1` (перезаписав старый `.1`) и создайте новый пустой
`LOGFILE`; иначе не делайте ничего. Сообщите, была ли ротация.

**Пример:** `./rotate.sh app.log 100` при `app.log` размером 200 байт печатает
`rotated`, появляется `app.log.1`, а новый `app.log` пуст (`0` байт).
